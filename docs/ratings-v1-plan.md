# 多来源评分接入第一版计划

状态：已批准实施
日期：2026-08-16

## 1. 目标

为已经上映、已经播出、正在连载、待回归或已经完结的作品补充可解释的多来源评分，并在 macOS 作品详情页集中展示：

- 豆瓣用户评分
- IMDb 用户评分
- TMDb 用户评分
- 烂番茄影评人评分
- 烂番茄观众评分（来源页面存在时）

每个分数必须保留来源、评分对象、量表、评价人数、来源链接和采集时间。评分只用于帮助判断口碑，不参与 Heat、榜单名次、走势或热度异动事件。

## 2. 第一版范围

### 2.1 纳入范围

- 新增独立的当前评分数据模型，不复用 `PopularitySignal`。
- 只处理至少有一个启用来源引用的当前作品。
- 只处理 `released`、`ongoing`、`returning`、`ended` 状态。
- 只使用稳定身份：TMDb ID、IMDb ID 或现有豆瓣 `sourceId`。
- 新增手动评分补全命令，并在每日调度完成后小批量自动补全。
- `GET /api/media/:id` 返回作品当前评分。
- macOS 作品详情页展示全部可用评分。
- OMDb 与 TMDb 凭据继续通过现有设置 API 保存，敏感值只返回配置状态和掩码。

### 2.2 明确不做

- 不为待播或身份未知作品提前抓取评分。
- 不按中文名或英文名搜索豆瓣，不抓豆瓣桌面 HTML，不绕过登录、验证码或访问限制。
- 不把评分换算成统一总分，不平均多个来源。
- 不让评分参与 Heat、榜单排名、热度走势或异动事件。
- 不在第一版保存完整评分历史。
- 不在第一版接入 IMDb 或 TMDb 分集评分、烂番茄季度评分。
- 不让 macOS 客户端直接访问任何评分网站或持有 API Key；全部外部访问仍由 NAS 后端完成。
- 不在列表卡片堆叠四到五个评分；第一版先在作品详情页完整展示。

## 3. 数据模型

新增 `MediaRating`，一条记录表示一个作品在一个来源和评分对象下的当前评分：

| 字段 | 含义 |
|---|---|
| `mediaItemId` | 所属作品 |
| `source` | `douban`、`imdb`、`tmdb` 或 `rotten_tomatoes` |
| `audience` | `users`、`critics` 或 `audience` |
| `value` | 原始评分数值 |
| `scale` | 原始量表，豆瓣/IMDb/TMDb 为 10，烂番茄为 100 |
| `voteCount` | 来源返回的评价人数；没有则为空 |
| `sourceUrl` | 可追溯到具体作品的来源链接 |
| `capturedAt` | 本次成功采集时间 |

使用 `mediaItemId + source + audience` 作为唯一身份，同一来源再次采集时只更新当前值。`MediaItem.ratingsCheckedAt` 记录作品最近一次完整评分尝试，用于轮转候选和控制刷新频率。

## 4. 来源策略

### 4.1 豆瓣

- 只选择已经存在 `MediaSourceRef(source=douban)` 的作品。
- `sourceId` 必须严格匹配 `douban-<数字 subject ID>`。
- 根据电影/剧集大类读取现有移动端详情接口 `/rexxar/api/v2/movie/<id>` 或 `/rexxar/api/v2/tv/<id>`。
- 复用当前豆瓣移动端请求头、可选 Cookie、`direct` 代理模式、统一 `SourceHttpClient` 和每个 origin 至少 2 秒限频。
- 只读取详情 JSON 的 `rating.value` 与 `rating.count`；无评分时不写空值。
- 遇到 403 或 429 时停止本轮后续豆瓣评分请求，保留已有评分，等待下一次日级机会。

这条路径不做标题搜索，因此不会把同名作品评分写错，也不会额外扫描豆瓣页面。

### 4.2 TMDb

- 只使用已有 `tmdbId`。
- 按电影/剧集大类读取详情，并同时请求 `external_ids`。
- 保存 `vote_average`、`vote_count`。
- 当作品缺少 IMDb ID 且 TMDb 返回合法 `tt` ID 时，只补空缺 IMDb ID，不覆盖现有身份。
- 继续支持 TMDb v3 Key 和 Bearer Token 两种现有配置形式。

### 4.3 IMDb 与 OMDb

- 只使用已有或由严格 TMDb 身份补出的 IMDb ID。
- 使用 OMDb `i=<IMDb ID>` 查询 IMDb 评分、票数、标准英文标题和类型。
- OMDb `Ratings` 中的 Rotten Tomatoes 百分比可作为烂番茄影评人分的安全兜底。
- OMDb 没有评分或返回 `N/A` 时，本轮不伪造零分，也不放宽为标题搜索 IMDb。

### 4.4 烂番茄

- 优先使用 OMDb 返回的标准英文标题，其次使用作品原名和展示名；去重后最多尝试三个非空标题。
- 搜索结果必须与作品电影/剧集大类一致。
- 沿用用户脚本的标题归一化：小写、去标点、去常见英文冠词和介词，再计算词集合重叠。
- 低于 50% 词重叠的候选直接拒绝；完全匹配优先，其次双向开头匹配，再按重叠率排序。
- 读取详情页内的 JSON 评分节点，旧页面再回退 `score-board` 属性。
- 成功时分别保存影评人和观众评分；直接页面失败时仍可保留 OMDb 给出的影评人分。
- 不猜测季度 URL，不把整剧评分标成某一季评分。

## 5. 调度与限频

- 所有请求使用统一 `SourceHttpClient`，同一外部 origin 的连续请求间隔不低于 2 秒。
- 服务按作品串行处理；单个来源失败不回滚同一作品已经成功写入的其他来源评分。
- 默认只处理 `ratingsCheckedAt` 为空或超过 24 小时的作品，优先从未尝试作品开始，再按 Heat 排序。
- 手动命令：`npm run enrich:ratings --workspace backend -- --limit=20`。
- 每日调度在来源同步和身份归并之后自动处理最多 12 部作品；小时调度和启动同步不执行评分补全。
- 命令和调度日志只输出计数、作品 ID 和脱敏错误，不输出 API Key、Cookie、代理或带密钥 URL。

## 6. API 与 macOS 展示

`GET /api/media/:id` 增加按来源和评分对象排序的 `ratings` 数组。无评分时返回空数组，不用 `0` 或 `N/A` 伪造。

macOS 详情页在标题元数据下增加“口碑评分”区：

- 每个来源独立卡片，显示来源名和原始量表，例如 `8.7/10`、`91%`。
- 有评价人数时显示格式化人数。
- 烂番茄影评人和观众分明确分开，不合并。
- 卡片使用现有设计色和紧凑布局，支持浅色与深色模式。
- 点击来源链接交给系统浏览器；没有链接时不显示可点击状态。
- 待播作品或空评分作品不显示空白评分区。

## 7. 配置与安全

- `TMDB_API_KEY`、`TMDB_BASE_URL`、`OMDB_API_KEY`、`OMDB_BASE_URL` 继续使用现有运行时设置。
- 把 OMDb 字段作为 IMDb 来源的可选配置展示，使 macOS 设置页可安全写入 NAS；它不改变 IMDb datasets 的手动来源状态。
- API Key 只保存在服务端环境文件，权限保持 `0600`；Mac 编辑草稿只驻留内存，保存后 readback 仍只读取掩码。
- 代码、测试 fixture、文档、日志和 Git 历史不得出现真实密钥。

## 8. 测试与验收

### 8.1 后端自动化

- Prisma 模型唯一身份和级联删除。
- 豆瓣详情评分解析、无评分、错误响应与 403/429 熔断。
- TMDb 电影/剧集评分及严格 IMDb ID 补全。
- OMDb IMDb 分数、票数与烂番茄兜底解析。
- 烂番茄电影/剧集类型过滤、标题阈值、JSON 与 `score-board` 两种解析。
- 候选只包含当前且已上映/已播作品；待播和无稳定身份作品被跳过。
- 多来源部分失败时成功来源仍写入，旧评分不被空响应清除。
- 评分不会改变 `heatScore`，不会创建排行事件。
- 详情 API 返回评分且不返回敏感配置。

### 8.2 macOS 自动化与实机

- Swift 模型可解码空评分和多来源评分。
- 详情页分别显示豆瓣、IMDb、TMDb、烂番茄影评人和观众分。
- 待播和无评分作品不出现空卡片。
- `scripts/test-macos.sh`、后端相关测试、类型检查和构建全部通过。
- 重建 `dist/WhatsNew.app`，核对签名、架构和 SHA-256，并在真实 NAS 数据上打开一部已上映作品完成视觉验收。

## 9. 第一版完成标准

1. 至少一部有豆瓣稳定 subject ID 的已上映作品能写入豆瓣评分。
2. 至少一部有 IMDb/TMDb 稳定身份的作品能写入 IMDb 与 TMDb 评分。
3. 烂番茄能写入影评人分；页面存在观众分时能同时写入观众分。
4. 同一作品各来源分数可同时存在且量表清楚。
5. 评分刷新不改变 Heat、榜单、播出状态或作品身份。
6. 密钥未进入源码、产物日志、测试 fixture 或 Git。
