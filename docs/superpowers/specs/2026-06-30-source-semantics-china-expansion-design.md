## 背景

WhatsNew 已经接入 TVmaze、TMDb、Trakt、TheTVDB、Netflix、优酷和爱奇艺，并在设置页展示更多规划来源。当前问题不再是“数据源数量太少”这么简单，而是用户需要在页面上看懂每个来源代表什么：它是上新、排期、平台榜单、社区热度、可看性、票房、口碑，还是元数据更新。

下一阶段先补齐来源口径体系，再继续接中国平台和市场信号。这样可以避免把 Trakt 日历、TMDb 趋势、Netflix 周榜、优酷热度、猫眼票房、豆瓣评分混成一个无法解释的“真实综合热度”。

## 目标

本阶段完成：

1. 给每个来源增加稳定的口径元数据，包括数据类型、覆盖范围、刷新节奏、访问方式和风险说明。
2. 在设置页和数据源页展示这些口径，让用户知道当前数据来自哪里、代表什么、是否最新。
3. 明确中国源扩展顺序：优酷、爱奇艺继续保留；腾讯视频、芒果TV、哔哩哔哩作为平台内容源；猫眼、灯塔、豆瓣作为市场与口碑信号源。
4. 保持 JustWatch、FlixPatrol 为商业或申请制来源，不伪装成免费可同步来源。
5. 保持 TheTVDB free-only 约束，不引入付费能力。

## 非目标

本阶段不做：

- 不实现新的中国站点采集 adapter。
- 不绕过登录、验证码、反爬或付费墙。
- 不新增用户账号或公网认证系统。
- 不计算跨来源综合总分。
- 不把商业 API、申请制 API 或网页可达性标记成已接入同步能力。
- 不改动现有 MySQL schema，除非后续实现发现前端展示无法仅靠静态目录满足。

## 来源口径模型

每个来源在注册表中增加以下静态字段：

- `signalKinds`：来源可能提供的数据类型。
- `coverage`：地区、媒体类型和平台覆盖说明。
- `cadence`：合理刷新节奏。
- `access`：免费公开、需要免费 Key、申请制、商业、公开页面、受限页面。
- `freshnessNote`：页面上展示的时效说明。
- `riskNote`：授权、反爬、商业或语义风险。

`signalKinds` 使用稳定枚举：

| 枚举 | 含义 | 示例 |
| --- | --- | --- |
| `release_calendar` | 播出、上映或上线排期 | TVmaze、TMDb、Trakt |
| `platform_catalog` | 某个平台片库或上新 | 优酷、爱奇艺、腾讯视频 |
| `platform_rank` | 平台内榜单或热度 | 优酷热度、Netflix Top 10 |
| `community_trend` | 社区趋势、观看、期待 | Trakt、TMDb |
| `metadata` | 作品基础资料和外部 ID | TMDb、TheTVDB、IMDb |
| `availability` | 可在哪个平台观看 | JustWatch |
| `box_office` | 票房、排片、影院市场 | 猫眼、灯塔 |
| `rating` | 评分和口碑 | IMDb、豆瓣 |
| `news_signal` | 资讯或舆情补充 | 时光网、微博等后续来源 |

前端不能只显示“已接入 / 规划中”。它需要同时显示“这个来源能贡献哪类信号”和“为什么不能直接同步”。

## 国际来源定位

### 已接入

- TVmaze：剧集排期和单集播出，适合补欧美剧日历，不提供电影。
- TMDb：电影、剧集趋势和基础元数据，适合发现全球上新和热门，不代表流媒体已可看。
- Trakt：电影与剧集社区热度、期待度和公开日历；日历是上映或播出排期，不是播放平台。
- TheTVDB：free-only 元数据和外部 ID，默认关闭，不做热度。
- Netflix：官方全球周榜，适合 Netflix 平台热度，不代表全网热度。

### 规划或受限

- IMDb：优先设计为免费非商业 datasets 导入，补充 `title.basics`、`title.ratings` 和 IMDb ID；不把 IMDb Developer 商业 API 当作默认方案。
- JustWatch：Streaming Charts 和可看性数据价值高，但 API 属于申请制或商业数据，当前保持商业/申请制状态。
- FlixPatrol：全球多平台榜单价值高，但 API 和大规模数据属于商业能力，当前保持商业状态。
- Apple TV+、Prime Video、Hulu、Disney+、Max：先作为规划源保留页面入口，后续逐个核对公开页面和接口可行性。

## 中国来源定位

### 平台内容源

- 优酷：首选中国平台源，继续直连，重点关注剧集、电影、综艺、动漫、短剧、独播和平台热度。
- 爱奇艺：次选平台源，继续直连；如果接口或页面稳定性差，只展示已验证能力。
- 腾讯视频：下一批平台源候选，关注剧集、综艺、动漫和热榜。
- 芒果TV：下一批平台源候选，关注综艺、剧集、预约和追更。
- 哔哩哔哩：下一批平台源候选，关注番剧、国创、纪录片和站内榜单。

### 市场与口碑源

- 猫眼专业版：强电影市场信号，公开页面可展示实时票房和部分网播热度，但完整数据可能需要 App 或专业版。先标记为公开页面/受限数据源。
- 灯塔专业版：强电影、剧综、动漫和网播热度信号，但偏专业数据产品。先标记为公开页面/受限数据源。
- 豆瓣：强中文口碑和评分信号，但不是上新源；采集必须谨慎，优先使用低频、页面可达性和手动校正辅助，不做高频爬取。
- 时光网：资讯与中文资料补充源，不作为核心热度源。

## UI 设计

### 设置页

设置页的数据源注册表增加三列：

- `信号类型`：显示该来源可能贡献的口径标签，例如“排期”“平台榜”“口碑”。
- `覆盖与刷新`：显示覆盖范围和刷新节奏。
- `访问方式`：显示免费、免费 Key、申请制、商业或页面受限。

已接入来源仍显示开关、代理、凭据和同步按钮。未接入来源显示禁用按钮和风险说明。

### 数据源页

数据源页不再只列最近同步运行。它改成“来源目录 + 最近同步状态”：

- 顶部显示已接入、规划中、商业/受限数量。
- 每个来源显示名称、分组、信号类型、接入状态、最近同步、最近采集数量。
- 对于商业或受限来源，展示不能同步的原因。

### 详情页和热度页

详情页和热度页继续展示原始来源、排名、数值和采集时间。后续实现可在来源标签旁补充口径 tooltip，但本阶段先不展开。

## 后端 API 设计

`GET /api/settings` 的每个来源返回新增口径字段。`GET /api/sources` 改为返回来源目录和最近运行状态，保留最近运行列表能力但不再作为前端唯一结构。

新增字段全部来自静态来源目录，不需要迁移数据库。来源同步和设置保存仍沿用现有运行时配置中心。

## 错误与风险

- 未联网或站点结构变化时，来源目录仍可显示，但同步状态不能伪装成功。
- 商业/申请制来源只能显示“需要申请/商业授权”，不能提供启用开关。
- 中国公开页面来源不能绕过登录、验证码或付费墙。
- 如果某个来源只提供元数据更新，不得生成热度信号。
- 如果一个来源只代表单个平台，页面必须显示平台名，不能写“全网”。

## 验证标准

- 后端来源目录测试覆盖新增字段和关键来源定位。
- 设置 API 测试覆盖新增字段不会泄露敏感配置。
- 数据源页测试覆盖来源目录展示，而不是只依赖同步记录。
- `npm run typecheck`、`npm test`、`npm run build` 通过。
