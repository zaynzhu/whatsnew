> 状态：来源透明度增强，面向“这条数据从哪里来”的可复核入口

## 背景

后端的发行记录、热度信号和事件记录已经保存 `sourceUrl`。前端目前多处只展示“来源 Trakt”或“来源 TVmaze”，没有把原始来源链接显式暴露出来。

用户在核对真实数据时，需要能从列表或详情快速打开原来源页面，而不是只看到来源名称。

## 目标

本阶段完成：

1. 增加可复用 `SourceLink` 组件。
2. 日历页的发行记录来源可点击。
3. 热度页的热度信号来源可点击。
4. 详情页的发行记录、当前热度信号和事件记录来源可点击。
5. 没有 `sourceUrl` 时继续显示纯文本来源。

## 非目标

本阶段不做：

- 不新增后端字段或数据库迁移。
- 不主动抓取或校验外部链接是否仍有效。
- 不把来源链接加入数据源注册表；注册表仍展示来源能力和状态。
- 不为 `sourceRefs` 补 URL，因为它们目前只有来源 ID 和外部 ID。

## 交互设计

来源链接显示为紧凑行内元素：

```text
来源 Trakt ↗
```

- 链接使用 `target="_blank"` 和 `rel="noreferrer"`。
- `aria-label` 使用 `打开 <来源名> 来源`。
- 视觉上沿用现有列表文本色，hover 时变为 teal。
- 外链图标使用 lucide `ExternalLink`。

## 安全与边界

- 只使用 API 已返回的 `sourceUrl`。
- 不拼接用户输入。
- 不展示任何 API Key、Token、Cookie、代理地址或本地路径。
- 空链接不渲染 `<a>`，避免误导用户以为可打开。

## 测试标准

必须覆盖：

- 热度页有 `sourceUrl` 的信号渲染可点击来源。
- 日历页有 `sourceUrl` 的发行记录渲染可点击来源。
- 详情页发行记录和当前热度信号渲染可点击来源。
- 详情页事件记录渲染可点击来源。
- 现有来源纯文本断言仍能通过。
- `npm run typecheck`、`npm test`、`npm run build` 通过。
