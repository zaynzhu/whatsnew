## 背景

WhatsNew 已接入 TMDb、TVmaze、优酷和爱奇艺，但外部来源的代理、凭据和启用状态仍依赖启动时读取的环境变量。当前 HTTP 请求层没有真正使用 `HTTP_PROXY` 或 `HTTPS_PROXY`，Trakt 在当前网络路径下还会被 Cloudflare 拦截。用户需要一个设置界面，用来管理网络代理、API Key、Token、Cookie、来源开关和连通性测试，并且保存后立即生效。

PixelReel 已有写回 `.env` 的设置页，可借鉴字段定义、白名单和备份策略。WhatsNew 不直接复制其页面或代码，而是在现有 Express、React、MySQL 和 adapter 架构中建立运行时配置中心。

## 已确认决策

- 使用全局默认代理，并允许每个数据源选择继承、直连或自定义代理。
- 代理用于解决网络可达性问题，国内来源默认直连，境外来源默认继承全局代理。
- 设置保存后立即生效，不要求重启服务。
- 代理、API Key、Token、Cookie 和 Base URL 在同一个设置界面管理。
- 设置页不增加登录或单独管理密码，因此项目必须保持在局域网或私有 NAS 环境中，不能直接暴露到公网。
- 配置继续持久化到 `backend/.env`，不新增 MySQL 配置表。
- 未实现、受阻或需要商务授权的来源必须如实标注，不能伪装成可用来源。

## 目标

设置页需要回答四个问题：

1. 当前全局代理是什么，是否可用。
2. 每个数据源是否已实现、已启用、凭据完整、网络可达。
3. 某个来源当前使用直连、全局代理还是自定义代理。
4. 配置修改后是否已立即应用，下一次测试或同步会走哪条网络路径。

## 非目标

- 不在本阶段一次性实现所有规划来源的采集 adapter。
- 不实现用户账号、权限系统或公网部署保护。
- 不在前端返回或长期保存敏感值明文。
- 不让连接测试写入影视、播出或热度数据。
- 不强制中断正在运行的同步任务；新配置从下一次连接测试或下一轮来源同步开始生效。

## 配置架构

### `RuntimeSettingsService`

后端新增单一运行时配置服务，负责：

- 启动时读取并解析 `backend/.env`。
- 提供经过类型校验的当前配置快照。
- 接受设置 API 的白名单字段更新。
- 写回 `.env` 前创建本地备份。
- 使用同目录临时文件和原子替换，避免进程中断时写坏配置。
- 写入成功后立即替换内存快照。
- 为敏感字段生成掩码和“已配置”状态，不向前端返回原值。

adapter 不再直接依赖启动时固定的 `env` 对象。每次来源同步开始时获取一份配置快照；同步进行中的配置保持一致，新配置从下一次测试或同步开始使用。

### 敏感值语义

以下字段视为敏感：

- 名称包含 `API_KEY`、`SECRET`、`TOKEN`、`PASSWORD` 或 `COOKIE` 的字段。
- `DATABASE_URL`。
- 包含用户名或密码的代理 URL。

GET API 只返回：

- `configured`：是否已配置。
- `maskedValue`：固定掩码和最多四位非敏感尾部提示。
- 字段类型、标签和校验要求。

前端输入框初始为空，以掩码作为占位。未提交该字段表示保留旧值；显式执行“清除”才会删除旧值。普通文本字段可以返回当前值。

## 代理模型

### 全局代理

全局设置包含：

- `HTTP_PROXY`
- `HTTPS_PROXY`

实施时从 PixelReel 的现有 `.env` 核对 `HTTP_PROXY`、`HTTPS_PROXY` 及对应的小写别名，只复制真实存在的值；缺失项保持为空，不推测或生成代理地址。任何日志、测试输出、API 响应和 Git 文件都不得暴露真实代理凭据。

### 每来源代理模式

每个来源拥有 `proxyMode`：

- `inherit`：按目标 URL 协议使用全局 HTTP 或 HTTPS 代理。
- `direct`：跳过全局代理并强制直连。
- `custom`：使用该来源自己的 HTTP/HTTPS 代理配置。

国内来源初始为 `direct`，境外来源初始为 `inherit`。自定义代理字段同样按敏感值处理。来源代理模式与自定义代理以白名单环境变量持久化，例如 `SOURCE_TMDB_PROXY_MODE`，具体键名由来源目录统一生成，不接受任意客户端键名。

### HTTP 请求层

统一 HTTP 客户端负责：

- 根据来源和 URL 协议选择代理。
- 设置超时和 `AbortSignal`。
- 保留当前每个外部服务至少 2 秒的请求间隔。
- 对错误进行分类和敏感信息脱敏。
- 禁止把代理 URL、API Key、Token 或 Cookie写入错误消息。

所有现有 adapter 分阶段迁移到统一 HTTP 客户端。只有完成迁移的来源才能在设置页显示“代理已接入”。

## 数据源目录

后端维护静态、类型安全的来源目录。每个来源包含：

- 稳定 `id` 和显示名称。
- 分组和用途。
- 实施状态。
- 默认代理模式。
- 所需凭据字段。
- 默认 Base URL。
- 轻量连通性测试目标。
- 是否支持手动同步。
- 是否支持启用开关。

实施状态分为：

- `active`：adapter 已实现并接入调度。
- `blocked`：adapter 已存在或已开始实现，但当前网络、授权或页面限制阻塞。
- `planned`：已纳入设计，尚未实现 adapter。
- `commercial`：需要商务申请或付费接口，当前不能直接启用。

## 后端 API

### `GET /api/settings`

返回：

- 全局代理字段和掩码状态。
- 来源目录。
- 每个来源当前配置、代理模式和凭据完整度。
- 最新同步状态与数据量。
- 最近一次连通性测试结果（如存在于当前进程内）。

### `PUT /api/settings`

只接受发生变化的白名单字段。更新成功后：

- `.env` 已原子写入。
- 内存配置已切换。
- 响应返回 `effectiveImmediately: true`。
- 不要求服务重启。

### `POST /api/settings/proxy/test`

分别测试直连、HTTP 代理和 HTTPS 代理。请求体可以包含尚未保存的新代理值，便于先测试再保存。结果包含路径、成功状态、耗时、HTTP 状态和归类后的错误，不返回测试 URL 中的敏感参数。

### `POST /api/sources/:source/test`

使用该来源当前或请求体临时配置执行轻量连接测试，不运行完整同步，不写业务数据。未实现来源可以测试公开页面可达性，但响应必须保留 `planned` 或 `commercial` 状态，不能因为页面可达就标记为 active。

### 现有同步 API

`POST /api/sources/:source/sync` 继续用于已实现来源。未实现、未启用或凭据不完整的来源返回明确的 4xx 错误和原因。

- `timeout`

- `unauthorized`
- `forbidden`
- `cloudflare_blocked`
- `credential_missing`
- `credential_invalid`
- `commercial_access_required`

- `http_error`

UI 使用中文摘要显示错误类型，保留经过脱敏的技术细节供排查。单个来源失败不影响其他来源。配置写入失败时继续使用旧的内存配置和原 `.env`。

## 风险与边界

- 用户明确选择不为设置页增加认证。代理、密钥和 Cookie 可被同网络中能访问后端的人修改，因此部署必须保持私有。
- `.env` 是唯一持久化事实来源；内存配置只是当前运行副本，服务重启后重新从 `.env` 加载。
- 保存立即生效不等于中断当前同步任务；当前任务使用启动时快照，下一轮任务使用新配置。
- JustWatch 和 FlixPatrol 可能需要商务 API；设置页展示它们不代表已经获得接口授权。
- 页面抓取来源可能因结构变化失效，必须通过来源状态和错误分类暴露问题。
